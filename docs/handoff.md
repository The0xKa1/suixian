## 2026-09-30 · 谱子与音频自动对齐
- 用户确认需要自动识别与内容匹配，尽量支持多种谱子；已授权增加仅在本机运行的识谱服务。
- 上传窗口先选择谱子与可选音频，再统一导入；支持混合选择 / 拖入、给当前谱子添加或替换音频。
- `recognize-score.ts` 调用本机 OMR，校验页覆盖与音符顺序；音频不发往服务端。
- Audiveris 识别印刷谱并转换为原始页序的音符参考；细节见 `research/omr.md`。
- `audio-alignment.ts` 全序列匹配音频特征，生成音符时间锚点和逐页匹配结果，禁止平均时长兜底。
- `import-audio.ts` 先验证时长再本地解码，限制体积 / 时长、支持取消并清理媒体和 AudioContext。
- `useAudioPlayback.ts` 以媒体真实时间驱动，处理播放承诺竞态、拖动进度、重播和资源释放。
- `ScoreDocument.audio` 保存 Blob、时长、时间锚点与匹配结果；替换音频沿用谱库记录 ID。
- 上传音频使用上述页界缓冲；麦克风模式下 PDF / 图片未获得可靠行坐标时仍按整页跟随。
- 新增 `scripts/dev.mjs` 同时运行前端和识谱服务，检查端口与服务身份后复用。

## 接续注意
- 阅读器使用 `mode: follow | audio`；无演示计时器，不自动请求麦克风。
- `audioPositionAtTime` / `audioTimeAtPosition` 统一双向映射；逻辑页在下一页首音时切换，可视缓冲允许提前显示下一页。
- OMR 页内拍数比例不是图像行坐标；音频缓冲只依赖页界时间，麦克风 PDF / 图片仍保持页级跟随。
- 轨道 transform 由 `useTrackSpring` 直接写入，JSX 不要再写 transform。
- 上传失败 / 取消只影响草稿；成功完成后才替换当前文档、更新谱库。
- 本机服务仅允许本机来源，文件不发往云端；不要把实验匹配描述为任意谱面精确识别。
- 下一步用授权实弹录音测试光标偏差、噪声、复杂和弦和 OMR 误读，再扩展反复 / 延音处理。
- 不恢复「如何翻页」「关于随弦」等说明区块；每份项目 Markdown 不超过 150 行。
