# 结构化乐谱与双视图

## 内容与布局
- `ScoreDocument.pages` 始终是导入时保留的页面；新文件原始 Blob 保存在 `originals`。
- `ScoreDocument.notation.version=1` 保存完整 MusicXML 来源、语义索引与笔记容器。
- 每份来源记录 `id / xml / originalPage / startBeat / durationBeats`；原页信息仅用于溯源。
- 每个小节和音符有稳定 ID，写入保留的 XML；索引记录声部、谱表、起始拍、时值、休止、延音与可用弦号 / 品位。
- 拍号、调号、歌词、力度、演奏记号等仍在完整 XML 内，不以扁平音高序列代替原始音乐内容。
- `annotations` 预留绑定小节 / 音符的文字笔记；本轮没有编辑器或笔记操作界面。

## 导入
- MusicXML 继续采用既有单乐器六线谱支持子集，同时保留完整 XML。
- PDF / 图片即使不附带音频也尝试本机识谱；Audiveris 的完整 XML 返回浏览器，不再仅保存简化参考。
- 识别失败时保留原件并显示原因；不能据此声称转换成功。配对音频仍必须通过原有匹配校验。
- 原谱库 PDF / 图片可点击「解析谱面」；如已有音频，使用保存的原始录音重新校验识别结果。
- 老 MusicXML 只有生成后的 SVG，无法可靠还原完整记谱语义，需要重新导入源文件。
- TAB 图片目前仅有品位顺序与占位时值，不能生成忠实乐谱；混合文件中存在此类页时整体保留原件。

## 显示
- 「重新排版」使用本地 OpenSheetMusicDisplay，将完整谱行组合成统一高度阅读页；桌面每页最多 3 行，窄屏 2 行。
- 标题、作曲者等保留在数据中，不在每张阅读页反复绘制；速度、歌词、指法等谱面内容保留。
- 「原件」显示导入图像；MusicXML / 示例没有原始纸张图像，对应视图称「导入版」。
- 视窗宽度改变会重新组行；原件始终可切回，视图选择按谱库记录保存。
- 动画沿用持续页面轨道、弹簧和减少动态效果设置；缓冲时保护有可靠坐标的当前谱行。
- 光标来自排版器真实音符与谱表几何。音乐进度比例只是有序查找键，不作为图像坐标。
- 光标的竖直范围固定为整组谱表，单音 / 和弦交替只改变横向位置；跨行或跨页才切换对应谱表范围。
- 若排版器未完整画出音符，或重排不能对应原事件，则回退原件并显示原因。

## 同步
- 录音始终使用同一媒体对象，切换显示不改变 `currentTime`。
- `AudioAlignment.anchors` 保存 `eventId / beat / time`；时间来自实际匹配，不按页数或长度平均分配。
- 原页面上的 `points` 保留兼容性；切换时从原始参考和锚点生成新布局的显示位置。
- 手动阅读位置也经音符身份对应；布局变化不改动音高、时值或事件顺序。
- 无真实首音锚点的目标页不能自动建立翻页同步，不能通过插值冒充声学证据。
- 未来编辑若改变音高、时值、顺序，必须重新验证音频对齐；仅笔记和布局调整不改音乐事件。

## 实际边界
- 完整保存识谱输出并不保证识谱正确；仍可能误读或漏掉原图中的符号。
- 沿用当前反复 / 跳转 / 不完整跨页延音等限制，尚无任意乐谱的完整转录保证。
- 当前每个原 PDF 页独立识别，再拼接其完整谱行，尚未合并跨原页的小节或乐器上下文。
- 当前 TAB 渲染暂不显示时值符干，完整节奏保留在 XML 中；演奏记号的视觉结果仍需与原件校对。
- 排版模块按需加载；较大 JS 包体仍有 Vite 构建提示。
- 后续优先做识别校对、笔记与有限编辑，再扩展复杂谱面和完整演奏结构。
